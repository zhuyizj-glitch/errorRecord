# 多账号与账号级数据隔离设计

日期：2026-09-27

## 目标

为错题集增加管理员和普通账号。管理员首次启动时初始化，并通过一次性邀请码开放注册；每个账号可以创建多个孩子，为孩子选择语文、数学、英语、物理、化学、生物、政治、历史、地理课程。账号之间的孩子、错题、图片、统计和复习数据相互不可见。

## 已确认的产品决策

- 注册使用一次性邀请码、用户名和密码。
- 管理员在网页后台生成、查看状态和作废邀请码。
- 使用逻辑隔离：共享一个 IMA 知识库，每条错题写入 `account_id`；Obsidian 按账号分目录。
- 现有女儿和儿子的数据迁入首次创建的管理员账号。
- 孩子与课程第一期支持新增、改名和调整课程，不提供删除或归档。
- 错题不删除；掌握后通过延长复习间隔降低出现频次。
- LLM 配置全局共享，仅管理员可以查看或修改，普通账号只能调用分析功能。
- 忘记密码由管理员重置；重置后用户必须修改临时密码。

## 架构

使用 Python 标准库 SQLite 保存 `accounts`、`sessions`、`invites`、`children` 和 `child_subjects`。数据库位于持久化目录 `config/app.db`，容器重建后仍保留。密码使用 `hashlib.scrypt` 加随机盐保存；邀请码、会话令牌只保存哈希。浏览器通过 `HttpOnly`、`SameSite=Lax` Cookie 持有随机会话令牌，后端从会话解析当前账号。

所有业务 API 默认要求登录。公开接口仅包括健康检查、系统初始化状态、首次管理员初始化、登录和邀请码注册。后端从会话取得 `account_id`，不接受客户端指定账号；处理 `child_id` 时验证孩子归属。未登录返回 401，跨账号资源统一返回 404。

SQLite 只保存账号体系和孩子课程配置。错题正文继续双写 IMA 与 Obsidian，避免重构现有存储架构。每条错题增加 `account_id`、`child_id` 和 `child_name`。IMA 中所有账号共享一个知识库，但读取、同步、统计和复习必须按元数据过滤。

## 数据模型

### accounts

- `id`：不可变随机 ID，例如 `acc_<uuid>`。
- `username`：规范化后唯一，不区分大小写。
- `display_name`：用户可修改的显示名。
- `password_hash`、`password_salt`。
- `role`：`admin` 或 `user`。
- `must_change_password`：管理员重置后为真。
- `created_at`、`updated_at`。

### sessions

- `id_hash`：随机会话令牌的 SHA-256 哈希。
- `account_id`、`created_at`、`expires_at`、`last_seen_at`。

会话默认有效 30 天。退出登录撤销当前会话；修改密码和管理员重置密码撤销该账号全部会话。

### invites

- `id`、`code_hash`、`created_by`。
- `created_at`、`expires_at`、`revoked_at`。
- `used_by`、`used_at`。

完整邀请码只在生成时返回一次。注册过程在一个数据库事务中校验并消费邀请码，避免并发重复使用。

### children 与 child_subjects

孩子使用不可变 `child_id`，同时保存显示名称和 emoji。`child_subjects` 从固定九门课中选择，调整课程只改变启用状态，不删除目录或错题。同一账号允许多个同名孩子。

## 文件结构

```text
错题集/
├── accounts/
│   └── acc_xxx/
│       └── child_xxx/
│           ├── 语文/
│           ├── 数学/
│           └── ...
└── _assets/
    └── accounts/
        └── acc_xxx/
            └── child_xxx/
                └── 数学/
```

用户名和孩子名称变化不影响目录。后端只用数据库中的 ID 拼接路径，并验证学科在白名单内，客户端不能传入文件系统路径。

## 页面流程

系统为空时只开放管理员初始化页面。管理员初始化成功后入口永久关闭，后续访问进入登录页。普通用户使用邀请码注册。登录后若没有孩子，进入创建孩子引导；创建时填写名称、选择 emoji，并从九门课中多选。

顶部保留孩子与课程切换器，并增加账号菜单。普通账号可修改显示名和密码、退出登录、管理自己的孩子与课程。管理员额外拥有账号与邀请码页面，可以生成或作废邀请码、查看使用状态、重置普通账号密码。LLM 设置页只对管理员开放。

密码被管理员重置后，旧会话全部失效。用户使用临时密码登录后只能进入修改密码页，修改成功后恢复业务页面访问。

## 历史数据迁移

迁移前创建 vault 和 SQLite 的带时间戳备份。首次管理员创建完成后，迁移脚本把现有 `daughter`、`son` 注册为该管理员的两个孩子，将 Markdown 和图片移动到新目录并补写 `account_id`、`child_id`、`child_name`。IMA 历史错题补写相同元数据。

迁移以题目 ID 和迁移日志保证幂等；执行中断后可以重跑。任何一步失败都保留原始备份并输出异常清单。日常同步遇到无 `account_id`、未知账号或未知孩子的数据时只记录异常，不猜测归属。

## 安全与异常处理

- 密码使用 scrypt 哈希，不记录明文。
- Cookie 为 `HttpOnly`、`SameSite=Lax`；在 HTTPS 部署时启用 `Secure`。
- 登录失败使用用户名与来源地址的短时限流，错误提示不区分用户名不存在和密码错误。
- 普通账号不能访问邀请码、账号列表、密码重置和 LLM 配置接口。
- 跨账号读取孩子、错题、图片、复习或统计统一返回 404。
- 邀请码无效、过期、已使用或已作废均拒绝注册，并提供可理解的页面提示。

## 验收标准

- 首次管理员初始化只能执行一次。
- 邀请码只能消费一次，过期或作废后不可使用。
- 两个账号可以创建同名孩子，但互相看不到数据。
- 九门课程可以任意组合，取消课程不删除数据。
- 上传、分析、保存、列表、详情、复习、统计、图片和同步均限制在当前账号。
- 普通账号不能读取或修改 LLM 密钥和管理员资源。
- 密码重置撤销旧会话，并强制用户修改临时密码。
- 现有女儿、儿子、Markdown、图片和 IMA 数据完整迁入管理员账号。

## EdgeOne Makers 部署约束

本设计中的账号边界、HttpOnly Cookie、管理员权限和 API 鉴权适用于 EdgeOne Makers，但 `config/app.db` SQLite 与本地 Obsidian 文件目录只适用于当前 Docker 常驻后端。若切换为 EdgeOne Cloud Functions，账号数据库应改为外部 PostgreSQL/MySQL（官方认证示例采用 Neon PostgreSQL），图片改为 COS 或 Blob，不能依赖函数本地文件长期保存。

FastAPI 可以部署为 EdgeOne Python Cloud Function；前端可作为 Pages 静态站点部署。IMA 调用需改为纯 HTTP 客户端或独立常驻服务，不能继续假设容器中存在 Node 和全局 `ima-skills` 文件。耗时分析任务还需改为可持久化任务状态，避免依赖进程内 `BackgroundTasks` 和内存任务列表。
